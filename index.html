The game we're building

10 minutesDesign

Sprout Empire is a garden-themed idle game. You tap a big sprout to grow sprouts one at a time. You spend sprouts on helpers (a watering can, a gardener, a greenhouse…) that grow sprouts for you every second. Each helper costs more than the last, so you're always saving up for something. Eventually you can replant: start over with nothing, but earn golden seeds that make everything grow faster forever.

The core loop

Every idle game is built on the same loop. Ours:

  1. Earn: tap the sprout, or wait while helpers produce.
  2. Spend: buy helpers (more income) or upgrades (multiply income).
  3. Grow: income goes up, the next purchase comes sooner, and bigger goals appear.
  4. Reset for power: replant for golden seeds once growth slows down, then go round again faster.

We build the loop in the same order players experience it. Part 2 gets earn and spend working with ugly placeholder art, because if clicking and buying isn't satisfying with grey boxes, pretty art won't save it. Saving comes next (Part 3) because an idle game that forgets your progress isn't an idle game. Only then do we add the features players expect (Part 4) and the art (Part 5).

How the project is organised

Here's the folder structure we'll end up with. You don't need to make it now; each chapter creates what it needs.

res://
├─ assets/      art, audio, fonts
├─ data/        generator, upgrade and achievement definitions (.tres files)
├─ scenes/      main screen and the small reusable pieces of UI
├─ scripts/     Game, Save, Settings and helpers
└─ ui/          theme and styles

We keep the rules and numbers (scripts/game.gd), the content (data/*.tres) and the screens (scenes/) apart. That separation is what makes an idle game easy to grow: adding a new helper is filling in a form, not writing code, and you can rebuild the whole interface without touching a single number. It's also what makes saving simple, because all the state lives in one place.

What is an autoload (singleton)? When should I use an autoload?

This is the most important structural decision in the game. Game owns the numbers and the rules; screens only display them and ask Game to change them. When Game changes something it emits a signal, and whichever screens care update themselves. The benefits pile up later: saving is "write Game's variables to a file", offline progress is "call Game's earn function", and you can redesign every screen without touching the economy.

Make saves safe

25 minutes

Losing a save is the worst thing that can happen to an idle game player: it can be months of progress. Our current code has a weakness. If the game crashes or the device dies while writing the file, you're left with half a file, and the player loses everything. We'll fix that with a standard technique.

Write to a temporary file, then swap it in. We write the new save to save.tmp. Only when that has fully succeeded do we rename the old save to save.backup.json and the temporary file to save.json. Renaming is nearly instant, so at any moment there's at least one complete save on disk. When loading, if the main save is damaged, we fall back to the backup. The ad format that fits idle games is the rewarded ad: the player chooses to watch one in exchange for, say, doubled offline earnings or ×2 production for an hour. Never force ads between taps.

Change the save format safely

30 minutes

Most updates don't touch the save format at all: new generators, upgrades and achievements just appear with default values (0 owned, not bought, locked). But sometimes you need to rename, split or reinterpret a saved value. That's what SAVE_VERSION and migrate() are for.

Each migration step upgrades a save by exactly one version and they run in order, so a save from 1.0 opened in 1.4 passes through every step it missed. Each step is written once and never changed again, so you never have to think about every possible old format at once. Migrations work on the plain Dictionary before Game sees it, which keeps Game's loading code simple: it only ever understands the newest format.

Never change an id in a .tres file after release, never reuse an old id for something different, and never delete a generator a player might own. To retire something, keep it in the database but hide it (for example, a retired checkbox your row scenes respect). A save that mentions an id the game no longer knows is simply ignored by our loading code, which is safe but means the player silently loses it.

When a newer save is loaded by an older game (a player with two devices, one not yet updated), our code warns and carries on. Unknown fields are ignored and kept nowhere, so the next save from the old game drops them. If that matters for your game, refuse to load saves with a higher version and tell the player to update.

Add content without breaking balance

Design

Idle-game updates are usually more of the same: new generators past the last one, more upgrades, more achievements, a second prestige layer. Some principles:

  • Add at the end, not the middle. A new tier 8 generator, priced around 10–12× the Moon Orchard, gives late players something new without changing anyone's current progress. A new tier between existing ones changes the pacing everyone already learned.
  • Buff, don't nerf. Players accept things getting better. Making something weaker after people have planned around it feels like having progress taken away. If something must come down, compensate: a one-off migration that grants golden seeds, or an apology gift.
  • Check with real saves. Load your latest late-game save code and ask: how long until the new content appears? Is the new upgrade so strong it makes the last hour pointless?
  • A second prestige layer (resetting golden seeds for something even more permanent) is the classic way to extend a mature idle game. It's the same pattern as replanting: one formula, one reset function, one tab.
  • Events and seasons (a Halloween pumpkin generator, a weekend ×2) bring players back. Check the date with Time.get_date_dict_from_system() and switch content on with a condition, rather than shipping a special build.

Model a pot in Blender

1–2 hours

Blender is a free 3D program. Even in a 2D game it's useful: you can show real 3D models in your interface, or render them into perfectly consistent 2D sprites. We'll model a flowerpot with a sprout in it.

3D is worth learning for an idle game because idle games need many similar assets (seven generators, each upgraded several times). Once a model exists, a new angle, colour or animation frame is a click away, and every image is lit identically. Drawing those by hand takes far longer and drifts in style.

  1. Install Blender from blender.org and open it. Click away the splash screen to get the default scene (a cube, a camera, a light).
  2. Learn to move the view: hold the middle mouse button and drag to orbit, Shift+middle-drag to pan, scroll to zoom. (No middle button? Edit → Preferences → Input → Emulate 3 Button Mouse, then use Alt+left-drag.)
  3. Click the cube and press X → Delete.
  4. Press Shift+A → Mesh → Cylinder. In the Add Cylinder panel that appears at the bottom-left, set Vertices 24, Radius 1, Depth 1.2.
  5. Press Tab for Edit Mode, then 3 for face selection. Click the top face. Press I (inset), move the mouse until the rim is thin, and click.
  6. Press E (extrude), type -1 and press Enter. The pot is now hollow.
  7. Taper it: orbit to see the bottom, click the bottom face, press S (scale), type 0.75, Enter. Press Tab to go back to Object Mode.
  8. Smooth it: right-click the pot → Shade Auto Smooth (called Shade Smooth with "Auto Smooth" in older versions). Then in the Properties editor on the right, click the blue wrench (Modifiers) → Add Modifier → Generate → Bevel, Amount 0.03, Segments 2. Edges now catch the light.
  9. Soil: Shift+A → Mesh → Cylinder, then S 0.85 Enter, S Z 0.1 Enter (flatten), and G Z to move it up until it sits just below the rim.
  10. Stem: Shift+A → Mesh → Cylinder, Radius 0.05, Depth 0.8; move it up (G Z) so it rises out of the soil.
  11. Leaf: Shift+A → Mesh → UV Sphere; S 0.3, then S Z 0.15 to flatten it into a disc, then S X 1.8 to stretch it into a leaf. Move it to the top of the stem and tilt it with R Y 20. Duplicate it with Shift+D, then R Z 180 for the second leaf.
  12. Colours: select the pot, open the red sphere tab (Material Properties), click New, set Base Color to terracotta. Give the soil a dark brown material and one leaf a green material. Select the other leaf, then Shift+click the green leaf, press Ctrl+L → Link Materials, so both share one material.
  13. Group it: Shift+A → Empty → Plain Axes, and name it Plant (double-click it in the Outliner at the top-right). Select all the plant parts, Shift+click the empty last so it's the active object, then press Ctrl+P → Object. Rotating the empty now rotates the whole plant.
  14. Save with Ctrl+S as art-source/plant.blend (outside your Godot project, unless you use direct .blend import below).

Writing calm, loopable music

  • Use a progression that circles. The chords I–V–vi–IV (in C: C, G, Am, F) end where they can start again, which hides the loop point.

Advanced sound effects

1–2 hours

Generated "bleeps" suit retro games. For a cosy garden, real sounds work better: a soft pop for clicks, rustling leaves, a little chime. You can record them yourself.

  1. Record. Your phone's voice recorder or any USB mic is enough. Record in a quiet room, close to the source: popping your lips or a cork for clicks, shaking a plant for rustles, tapping a glass for chimes. Record several takes of each.
  2. Clean. In Audacity, select a second of silence (room noise only), choose Effect → Noise Removal and Repair → Noise Reduction → Get Noise Profile, then select everything and run Noise Reduction again with OK.
  3. Shape. Trim, then Effect → Fading → Fade In/Fade Out on the very edges. Effect → EQ and Filters → Filter Curve EQ to cut rumble below ~100 Hz. Effect → Pitch and Tempo → Change Pitch to make a pop smaller (higher) or bigger (lower).
  4. Layer. Great sounds are often two sounds: import a pop and a chime on two tracks, align them, and use Tracks → Mix → Mix and Render. A "purchase" sound might be a coin clink layered with a soft rustle.
  5. Level. Normalize every effect to the same peak, then set relative loudness with each AudioStreamPlayer's Volume dB in Godot, where it's easy to tweak.
  6. Vary. Export three or four takes of each sound and put them all in an AudioStreamRandomizer (with Playback Mode Random (avoid repeats) plus a little random pitch and volume).

Effects in the mixer

What audio effects does Godot have?
  • Reverb for big moments. Add a bus SFX Reverb (sending to SFX) with an AudioEffectReverb, and route the achievement and golden sounds to it. They'll sound bigger than clicks.
  • Duck the music. On the Music bus add an AudioEffectCompressor with Sidechain set to SFX. When an effect plays, the music dips slightly so it's heard clearly.
  • Muffle behind menus. Add an AudioEffectLowPassFilter to Music, disabled by default, and enable it while a dialog is open with AudioServer.set_bus_effect_enabled(bus_index, 0, true).

Need sounds you can't record? Freesound has hundreds of thousands. Filter by licence (CC0 is simplest) and add the rest to your credits.

Performance for idle games

30 minutes
How do I optimise a Godot game? Where should I start optimising?

An idle game rarely struggles to reach 60 frames per second. Its problem is the opposite: it runs for hours, so wasted work becomes heat, fan noise and flat batteries.

  1. Low processor mode (we turned it on in Part 1) sleeps between frames. Keep it on.
  2. Cap the frame rate. Project Settings → Application → Run → Max FPS: 60 (or 30 on mobile via a setting). Nothing in an idle game needs 144 fps.
  3. Do expensive work less often. Like the Stats tab, anything that doesn't need to update every frame should update a few times a second, or only when its signal fires.
  4. Cap counts of anything that accumulates: particles, physics bodies, floating texts, log lines.
  5. Measure. Use the Profiler and Monitors → Time → Process before optimising anything. Guesses about what's slow are usually wrong.
  6. Download size for web: use Ogg (not WAV) for audio, keep textures at the size they're shown, and enable compression on your host (itch.io does this for you).

GDExtension: native code

Reading
What is GDExtension? How do I write a C++ GDExtension?

GDExtension lets you write parts of the game in C++ (or Rust, Swift and others through community bindings) and use them from GDScript as if they were built-in nodes. You'd reach for it to:

  • do maths far faster than GDScript allows (a big-number type for games beyond 10308, or simulating millions of things);
  • use a C or C++ library (a platform SDK, a compression library);
  • use a community extension someone else built, which is how GodotSteam works.

Most idle games never need it. GDScript is fast enough for anything Sprout Empire does by a huge margin, and native code must be compiled separately for every platform you ship to. Profile first; reach for GDExtension only when a measured hotspot can't be fixed by doing less work.

Troubleshooting

Reference

The errors beginners hit most often, what they mean, and the usual fix. Errors appear in the Debugger → Errors tab and the Output panel; double-click one to jump to the line.

Message (or symptom)Usual cause and fix
Node not found: "%Something"The node isn't marked Access as Unique Name, is spelled differently, or is in a different scene. Unique names only work inside the same scene.
Invalid access to property or key … on a base object of type 'null instance'A variable holds nothing. Usually an @onready node that wasn't found, or using a node before _ready. Check the name, and check that data is set before add_child for rows.
Identifier "Game" not declared in the current scopeThe autoload isn't registered, or its name is different. Check Project Settings → Globals → Autoload.
Could not find type "GeneratorData", or it isn't in the Create Resource listThe script with class_name has an error or hasn't been saved. Fix and save it, then Project → Reload Current Project.
Mixed use of tabs and spaces for indentationPasted code with spaces into a file that uses tabs. Select all and use Edit → Indentation → Convert Indent to Tabs in the script editor.
Cannot infer the type of "x" variable because the value doesn't have a set typeYou used := with something that could be anything (like a value from a Dictionary). Write the type explicitly: var x: float = d["x"].
A dialog appears as soon as the game startsIts Visible property is on. Turn it off in the Inspector (or click the eye in the Scene dock).
The save doesn't load / offline progress is zeroAutoload order: Game must come before Save. Also check you closed the game normally or waited for an autosave.
Nothing happens when clickingSomething on top is catching clicks. Set Mouse → Filter to Ignore on overlay Controls like Effects, toasts and floating text.
Sound doesn't playCheck the player has a Stream, its Bus exists (names are case-sensitive), and the bus volume isn't muted. On the web, sound starts only after the first click.
The web export shows a blank page or an error about the file protocolYou opened index.html directly. Use Run in Browser, or a local web server. On a host, check every exported file was uploaded.
Pixel art looks blurrySet Rendering → Textures → Canvas Textures → Default Texture Filter to Nearest, and show art at whole-number scales.
Attempt to call function … in base 'previously freed'Code is using a node after queue_free(). Check is_instance_valid(node) first, or disconnect signals before freeing.
Numbers show as "1000.00K"Your NumberFormat.short is missing the + 0.000001 guard.

Where to go next
